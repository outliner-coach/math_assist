# 응용문제 코어 작업 규칙

## 담당 범위

이 디렉터리는 전 학년 응용문제의 공통 계약, 결정적 제작기 실행, 독립 검산,
정량 시각 검증, 출시 원장 판정과 2·5·6학년 연결 장치를 담당한다. 학년별 화면
문구·레이아웃, 원천 교육과정 JSON, 기존 기본 문제 은행과 localStorage 키의
소유권은 이 모듈에 없다.

## 경계

- 실행 가능한 제작기 목록과 출시 원장 스냅샷을 분리한다. 제작기 객체를 그대로
  원장에 공유하거나 실행 등록만으로 승인 상태를 추론하지 않는다.
- 학습자 후보 선택은 실행 항목, 프로젝트 책임자 승인 정보, 깊게 동결된 출시
  스냅샷이 같은 `familyId@version`으로 정확히 하나씩 일치할 때만 성공한다.
- `draft`, `quarantined`, `retired`는 신규 문제 생성에 사용하지 않는다. 과거
  `retired`·`quarantined` 스냅샷의 상태 판정은 제작기 제거 뒤에도 유지한다.
- 제작기와 독립 검산기는 정답 계산 함수를 공유하지 않는다. 증명 구현을 바꾸면서
  신뢰 목록을 같은 경로에서 자동 승인하지 않는다.
- 필수 정량 시각 검증이 실패하면 문항을 차단한다. 문제값과 모순되는 개략도로
  낮추거나 제출 전 정답 전용 값을 직렬화하지 않는다.
- 학년별 연결 장치는 공통 출처를 보존하되 기존 미션 ID, 세션 길이·난이도 분배,
  저장 키와 구형 출처 없는 스냅샷의 읽기 의미를 바꾸지 않는다.

## 구현 방식

- 새 문제 유형은 안정된 `familyId`, 증가하는 버전, 결정적 시드와 변형 번호를
  사용한다. 승인된 동일 버전의 수학 의미를 고치지 않고 새 `draft` 버전을 만든다.
- 허용 매개변수 영역이 유한하면 전수 검사한다. 그 밖에는 독립 불변식, 모든 경계
  분류와 고정 시드 표본을 함께 검사하며 표본 성공만으로 증명을 대신하지 않는다.
- 학년별 레지스트리는 해당 학년 제작기만 가져온다. 전체 카탈로그는 감사와 내부
  검수에서만 세 학년 레지스트리를 합쳐 학년 하나의 번들을 불필요하게 키우지 않는다.
- 세션 생성 실패는 저장 전에 결정적 대체 시드로 제한 횟수만 재시도한다. 필요한
  문항 수를 채우지 못하면 짧은 세션이나 잘못된 문항을 저장하지 않는다.

## 테스트

- 계약 parser는 성공 예제뿐 아니라 잘못된 enum, 참조, 승인 필드와 상태 전이를
  거부하는 쌍 테스트를 가져야 한다.
- 제작기 변경은 동일 시드 재현, 독립 정답 검산, 경계값, 구조 다양성과 오개념
  연결을 검사한다.
- 시각 변경은 문제·정답·모델 수치, 위상, 0 영역, 라벨 포함, 균일 배율과 제출
  전 부재·제출 후 공개를 한 쌍으로 검사한다.
- 레지스트리나 연결 장치 변경은 승인 상태 네 종류, 중복·누락 원장, 구형 세션,
  2학년 기록·보상, 5·6학년 문항 수·난이도·학년 간 저장 격리를 회귀 검사한다.
