# 4학년 Bridge 단원별 출시 범위

## 현재 상태

4학년은 교육과정 원장에서 `released`이며 홈의 1·2·3·4·5·6학년 선택에
노출된다. `/grade/4`는 검증된 단원을 선택하고,
`/grade/4/mission?unitId=<id>`는 선택 단원의 3문제 Bridge 활동을
제공한다. 6학년 공개 범위는 별도의 Study 계약을 따른다.

  완전한 분수·대분수만 허용하며 동치인 가분수·대분수를 같은 값으로 비교
- 저장: `mathAssist_grade4Progress`와 공통 `mathAssist_attemptReceipts_v1`; 다른 학년 키와 분리
- 풀이장: 활동 실행·문항 변형별 안정적인 로컬 저장 키 사용

## 비활성 범위

원장에서 4학년으로 배정된 나머지 8개 성취기준은 `planned`를 유지한다.
문제 은행, 정답·그림 쌍 검사, 모바일 E2E가 모두 없는 단원은 화면에
만들거나 홈에서 가능하다고 표시하지 않는다.

## 공개 게이트

1. `npm run validate:curriculum`, `npm run validate:grade4`, `npm run audit:missions`가 오류와 경고 없이 끝난다.
2. 집중 단위 테스트와 전체 테스트, lint, TDD guard, production build가 통과한다.
3. 4학년 E2E에서 형식 오류 미기록, 오답→정답 영수증 순번, 로컬 진도, 3문제 완료, 작은 화면 폭을 확인한다.
4. 원장의 `releaseState.grade4 = released`와 홈의 지원 학년 4 노출은 같은 통합 변경으로 유지한다. 둘이 다르면 curriculum validator가 실패한다.

## 유지보수 계약

- 추가 문제는 반드시 원장에 4학년으로 배정되고 같은 변경에서
  `released`·`existing-reference`로 승격한 성취기준을 사용한다.
- 검증기는 각 단원을 독립적으로 10문제·K4/A4/R2·추론 문제군
  2개·표현 2개 이상인지 확인한다. 전역 합계만 맞추면 통과할 수 없다.
- 선수 기준 코드는 학습 순서 근거이며 해당 단원 문제의 출시 참조로
  세지 않는다.
- 정답 전용 합성값은 제출 전 DOM 또는 접근성 트리에 만들지 않는다.
- 소수 자리표는 문제에 주어진 자리 숫자는 보이되 합성된 소수 답을
  제출 전 하나의 DOM 문자열로 만들지 않는다.
- 분수 띠의 등분 수와 색칠 칸은 문제의 분모·분자에서 직접 만들고,
  합·차나 빠진 분자는 제출 전 DOM·접근성 이름에 만들지 않는다.
- 소수 덧셈·뺄셈은 피연산자와 합·차·빠진 항을 백분의 일 단위
  정수에서 계산한다. 세로셈은 피연산자 자리만 표시하고 결과는 제출
  전 DOM·접근성 이름에 만들지 않는다.
- 규칙표는 제시된 수열·대응쌍·계산식만 표시한다. 빈칸 값과 먼 단계
  결과는 제출 전 시각 설정·DOM·접근성 이름에 만들지 않는다.
- 등식 균형 모형은 문제에서 제시한 양과 빈칸만 표시한다. 빠진 양은
  제출 전 시각 설정·DOM·접근성 이름에 만들지 않는다.
- 수직·평행 모형은 문제·정답·풀이와 같은 두 방향각에서 선의 방향과
  직각 표식을 만든다. 수직은 방향 차 90°, 평행은 방향 차 0°라는
  조건을 모든 변형에서 검사한다.
- 도형 이동 모형은 시작 위치, 이동량, 기준선, 회전 중심만 시각
  설정에 저장한다. 좌표 답과 목표 도형은 같은 변환 함수에서 계산하되
  확인 전 DOM·접근성 이름에 만들지 않는다.
- 조건형 문제는 모든 숫자 변형을 직접 계산한 참값과 대조한다.
- 어림값은 화면에 표시된 수와 단위에서 파생하며, 방법 비교는 모든
  변형에서 오차가 더 작은 한 방법만 정답이 되도록 검사한다.
- 유효한 확인만 시도 영수증을 만들며 원답 문자열과 풀이장 획은 영수증에 저장하지 않는다.
