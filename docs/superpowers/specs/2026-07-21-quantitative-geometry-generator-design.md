# 정량 도형 생성기와 세 도형 겹침 설계

- 상태: 승인됨
- 기준일: 2026-07-21
- 첫 적용 범위: 5학년 `area-001`의 `three_shape_overlap`
- 장기 적용 범위: 전 학년의 정량 시각 문제 유형

## 1. 배경

현재 `three_shape_overlap` 문제는 문제 수치에서 일곱 영역의 넓이를 정확히 계산하지만, 렌더러는 각 영역을 떨어진 단위 셀 묶음으로 배치한다. 셀 수는 맞아도 세 개의 실제 도형이 겹친 모습이 아니므로, 학습자는 문제에서 말하는 도형과 그림 사이의 관계를 읽을 수 없다.

정량 그림은 장식이 아니다. 문제에서 길이, 넓이, 둘레 또는 겹침 관계를 제시하면 렌더된 기하도 같은 값을 가져야 한다. 특정 도형 이름이나 교과서 예시의 외형을 복제하는 것보다 문제의 수학 모델과 실제 렌더 기하가 일치하는 것이 우선이다. 다만 문제에서 평행사변형, 마름모, 사다리꼴처럼 도형 종류를 명시한다면 생성기는 그 도형의 정의도 함께 만족해야 한다.

이번 변경은 한 SVG를 눈으로 조정하는 작업이 아니다. 수백 개 문제 유형으로 확장할 수 있도록 수학 모델, 유형별 기하 생성기, 공통 검증기, SVG 렌더러를 분리하고 그 첫 구현으로 세 도형 겹침 문제를 교체한다.

## 2. 목표

1. `three_shape_overlap`을 세 개의 실제 폐곡선 도형이 겹치는 교과서형 그림으로 렌더한다.
2. 각 도형과 일곱 원자 영역의 실제 넓이가 문제 모델과 일치하게 한다.
3. 넓이가 0인 영역은 기하, 라벨, DOM 어디에도 만들지 않는다.
4. 문제에 주어진 단독 영역과 삼중 겹침 값만 표시하고, 풀이 과정에서 구해야 하는 이중 겹침값은 제출 전에 DOM과 접근성 이름에 만들지 않는다.
5. 이후 길이·둘레·넓이 문제 유형이 같은 `모델 → 생성 → 검증 → 렌더` 경계를 재사용할 수 있게 한다.
6. 구형 저장 세션처럼 `visual.model`이 없는 문제도 기존 입력값에서 같은 모델과 기하를 결정적으로 복원한다.

## 3. 이번 범위에서 하지 않는 일

- `basic_shape`, `l_shape`, `overlap_rectangles`, `rectangle_square`를 이번 변경에서 함께 교체하지 않는다.
- 모든 도형 문제를 하나의 범용 수치 최적화 엔진으로 풀지 않는다.
- 교과서 이미지의 특정 평행사변형·마름모·사다리꼴 조합을 현재 템플릿에 강제로 추가하지 않는다.
- 현재 `three_shape_overlap` 문제의 정답 규칙이나 문제 수를 바꾸지 않는다.
- 정량값이 맞지 않는 경우 근사 그림이나 장식용 대체 그림을 표시하지 않는다.

## 4. 검토한 접근

### 4.1 문제 유형별 기하 생성기와 공통 검증기 — 채택

각 시각 문제 유형이 자신의 수학 모델을 기하 좌표로 변환하고, 공통 검증기가 결과의 면적·길이·둘레·위상을 다시 측정한다. 렌더러는 검증된 기하만 SVG로 표현한다.

유형마다 교육적으로 적절한 모양을 선택할 수 있고, 공통 정확성 계약을 유지할 수 있다. 첫 생성기는 세 도형 겹침이지만 이후 문제 유형도 같은 인터페이스로 추가한다.

### 4.2 범용 기하 제약 풀이 엔진 — 선택하지 않음

모든 조건을 수치 최적화로 풀면 표면상 범용적이지만, 수렴 실패와 비결정성, 비정상적인 도형, 환경별 부동소수점 차이를 학습 경로에 들인다. 문제 생성과 저장이 결정적이어야 한다는 현재 계약에 맞지 않는다.

### 4.3 문제별 SVG 프리셋 — 선택하지 않음

소수 문제에는 빠르지만 매개변수 조합과 문제 유형이 늘어날수록 사람이 모든 좌표를 검증할 수 없다. 고정 좌표가 문제값과 어긋났던 기존 결함을 반복한다.

## 5. 핵심 정확성 계약

### 5.1 선언된 값은 정확해야 한다

문제에 수치로 선언된 길이, 둘레, 넓이와 교차 넓이는 기하 모델 좌표에서 같은 값이어야 한다. 검증 시 사용하는 허용치는 교육적 근사가 아니라 부동소수점 표현 오차만 흡수한다.

```text
epsilon = max(1e-9, abs(expected) * 1e-9)
abs(measured - expected) <= epsilon
```

기존 결정 문서의 `비율 오차 ±10%`는 선언되지 않은 보조적 시각 비율에만 적용할 수 있다. 문제에 명시된 정량값에는 적용하지 않는다.

### 5.2 모양의 이름도 정량 계약이다

문제에서 직사각형, 평행사변형, 마름모, 사다리꼴 등을 명시하면 생성기와 검증기는 평행, 직각, 같은 변 길이 같은 정의를 확인해야 한다. 현재 템플릿은 단순히 세 도형이라고 하므로, 이번 생성기는 특정 도형 종류를 주장하지 않는 단순 다각형 세 개를 만든다.

### 5.3 SVG 확대·축소는 수학 모델을 바꾸지 않는다

기하 생성기는 문제 단위의 모델 좌표를 반환한다. 렌더러는 하나의 균일 배율과 이동만 적용하고 `preserveAspectRatio`를 유지한다. 가로와 세로를 서로 다른 비율로 늘려 각도와 길이 관계를 바꾸지 않는다.

## 6. 아키텍처

```text
템플릿 매개변수
    ↓
문제 유형의 수학 모델
    ↓
QuantitativeGeometryAdapter
    ├─ 기하 생성
    └─ 공개 가능한 라벨 의도 생성
    ↓
공통 QuantitativeGeometryValidator
    ├─ 좌표·면적·길이 검사
    ├─ 영역 위상·0 영역 검사
    ├─ 폐곡선·교차·라벨 위치 검사
    └─ 문제 모델 재구성 검사
    ↓
ProblemDiagram SVG 렌더러
```

### 6.1 공통 기하 기본형

공통 계층은 다음 의미를 표현한다.

```ts
type Point = { x: number; y: number }

type QuantitativeShape = {
  id: string
  polygon: Point[]
}

type QuantitativeLabel = {
  regionKey: string
  anchor: Point
  visibility: 'given' | 'identifier'
}

type QuantitativeGeometry = {
  shapes: QuantitativeShape[]
  labels: QuantitativeLabel[]
  viewBox: { minX: number; minY: number; width: number; height: number }
}
```

기하 결과에는 완성된 A·B·C 폐다각형만 둔다. `labels`는 숫자 자체가 아니라 공개 가능한 영역과 위치만 나타낸다. 렌더러는 원래 문제 props에서 `given` 값만 읽어 텍스트를 만든다. 이중 겹침처럼 풀이 과정에서 구해야 하는 값은 기하 결과와 라벨 payload 어디에도 숫자로 저장하지 않는다.

실제 TypeScript 이름과 파일 분리는 구현 계획에서 저장소 관례에 맞춰 확정하되, 수학 모델과 SVG 컴포넌트 사이에 이 경계를 유지한다.

### 6.2 문제 유형별 어댑터

각 어댑터는 다음 책임만 가진다.

1. 문제 모델이 지원하는 위상인지 확인한다.
2. 선언된 값으로 원자 영역 좌표를 결정적으로 생성한다.
3. 어떤 값이 문제에 주어졌고 어떤 값이 풀이 과정인지 라벨 의도로 구분한다.
4. 공통 검증기에 기대 측정값을 제공한다.

어댑터는 React, DOM, Tailwind, 접근성 문자열을 알지 않는다.

### 6.3 공통 검증기

검증기는 생성기와 별도로 다음을 다시 확인한다.

- 모든 좌표가 유한수인지
- A·B·C가 단순한 볼록 폐다각형이고 양의 넓이를 가지는지
- 신발끈 공식으로 계산한 각 도형의 넓이가 모델과 일치하는지
- 완성된 A·B·C 경계를 볼록 다각형 clipping으로 다시 교차해 `AB`, `AC`, `BC`, `ABC` 넓이를 구할 수 있는지
- 교차 넓이에서 `ABC`를 빼고 포함배제를 적용해 재구성한 일곱 원자 영역이 모델과 일치하는지
- 모델에서 0인 원자 영역의 재측정값이 부동소수점 epsilon 안에서 0인지
- 라벨 기준점이 해당 원자 영역 내부에 있는지
- 문제에 공개되지 않은 값이 라벨 payload에 없는지

생성기와 검증기가 같은 영역 분류를 공유하지 않도록, 검증기는 생성기가 반환한 완성 다각형 좌표만 입력받아 교차와 원자 영역 넓이를 다시 계산한다. 생성기가 `AB만`이라고 주장하는 중간 면이나 membership 표시는 검증 입력으로 받지 않는다.

## 7. 세 도형 겹침 생성기

### 7.1 입력 모델

기존 `buildThreeShapeOverlapModel`이 다음 일곱 영역을 계속 계산한다.

```text
A만, B만, C만, AB만, AC만, BC만, ABC
```

각 도형의 넓이는 원자 영역 합으로 재구성된다.

```text
A = A만 + AB만 + AC만 + ABC
B = B만 + AB만 + BC만 + ABC
C = C만 + AC만 + BC만 + ABC
```

현재 템플릿 표본 `shapeArea=29`, `exclusiveAreas=[18,20,22]`, `tripleOverlap=5`는 `AB만=4`, `AC만=2`, `BC만=0`을 만든다.

### 7.2 첫 구현이 지원하는 위상

현재 `area-001` 템플릿은 모든 허용 매개변수에서 다음 형태를 만든다.

```text
shapeArea = e + 8 + k
exclusiveAreas = [e, e + 2, e + 4]
ABC = 2 + k
AB만 = 4, AC만 = 2, BC만 = 0
```

따라서 첫 생성기는 다음 조건을 만족하는 모델만 지원한다.

- `A만`, `B만`, `C만`, `ABC`가 모두 양수다.
- 이중 겹침 영역 중 정확히 하나가 0이고 나머지 둘은 양수다.
- 아래 폐형식 구성의 내부 띠가 기준 도형 안에 들어가는 적합성 부등식을 만족한다.

0인 쌍이 `BC`가 아니면 도형 이름을 순환 배치해 0인 쌍이 `BC`인 정규형으로 만든 뒤, 생성 후 원래 이름으로 되돌린다. `ABC=0`, 단독 영역 0, 이중 겹침이 둘 이상 0, 이중 겹침이 모두 양수인 모델은 첫 구현의 지원 범위가 아니다. 현재 템플릿 검증기는 이런 모델을 만들지 않음을 전 범위 표본으로 확인한다. 이후 같은 문제 유형에 다른 위상이 필요하면 해당 위상의 폐형식 생성기를 별도 설계와 테스트로 추가한다.

### 7.3 `BC만=0` 정규형의 폐형식 구성

다음 기호를 사용한다.

```text
S = 세 도형의 공통 넓이
a, b, c = A만, B만, C만
x, y = AB만, AC만
t = ABC
BC만 = 0
```

기준 도형 A를 `S × 1` 직사각형으로 둔다. B가 A 안에서 차지하는 부분은 위쪽 가로 띠, C가 A 안에서 차지하는 부분은 오른쪽 세로 띠로 만든다.

```text
B 띠 높이 h = (x + t) / S
C 띠 너비 w = t / h
C 띠 높이 q = (y + t) / w
```

그러면 다음 값이 폐형식으로 보장된다.

```text
area(A ∩ B) = S × h = x + t
area(A ∩ C) = w × q = y + t
area(A ∩ B ∩ C) = w × h = t
area((B ∩ C) - A) = 0
```

`q <= 1`이어야 두 띠가 A 안에 들어간다. 이는 `a >= x*y/t`와 동치이며 생성 전에 검사한다. 현재 템플릿에서는 `a=e`, `x=4`, `y=2`, `t=2+k`이므로 모든 허용값에서 만족한다.

B의 A 바깥 부분은 A의 윗변에 붙은 사다리꼴, C의 A 바깥 부분은 A의 오른쪽 변에 붙은 사다리꼴로 만든다. `0 < rho < 1`을 상수로 고정하고 높이 `dB`, `dC`는 사다리꼴 넓이 식에서 역산한다. 바깥 부분의 꼭짓점은 다음과 같이 고정한다.

```text
B 바깥: (0,0), (S,0), ((1+rho)S/2,-dB), ((1-rho)S/2,-dB)
C 바깥: (S,0), (S,q), (S+dC,(1+rho)q/2), (S+dC,(1-rho)q/2)
```

B의 바깥 밑변은 `0 <= x <= S` 안에 있고 전체 바깥 부분은 `y <= 0`에 머문다. C의 바깥 밑변은 `0 <= y <= q` 안에 있고 전체 바깥 부분은 `x >= S`에 머문다. 따라서 두 바깥 부분은 경계점 외에 면적으로 겹치지 않는다. 이 중앙 정렬과 `rho` 범위는 띠와 사다리꼴을 합친 B·C 경계가 볼록하도록 보장한다.

마지막에는 행렬식이 1인 affine 변환으로 긴 `S × 1` 기준 도형을 읽기 좋은 종횡비로 바꾼다. 이 변환은 모든 넓이와 교차 넓이를 보존한다. 회전·이동과 SVG의 균일 화면 배율은 그 뒤에 적용한다.

생성된 모양은 특정 사각형 종류를 주장하지 않는다. 라벨이 들어갈 수 없는 종횡비나 최소 시각 폭이면 근사 조정하지 않고 지원되지 않는 배치로 실패시킨다.

### 7.4 렌더링

- 세 도형은 서로 구분되는 낮은 불투명도의 채움과 명확한 외곽선을 가진다.
- 원자 영역의 실제 경계를 보존하면서 교차 채움이 읽히도록 한다.
- `A`, `B`, `C` 식별자는 외곽선 가까이에 둔다.
- `A만`, `B만`, `C만`, `ABC`에는 문제에 주어진 넓이를 표시한다.
- `AB만`, `AC만`, `BC만`에는 숫자, `data-*` 값, 접근성 값을 표시하지 않는다. 현재 문제처럼 영역 이름도 주어지지 않았다면 `AB`, `AC`, `BC` 문자도 표시하지 않는다.
- 0인 영역에는 면, 빈 공간 표식, `0` 라벨을 만들지 않는다.
- 기존 `한 칸 = 1 단위²` 설명은 제거한다.
- 접근성 이름에는 문제에 이미 주어진 값과 세 도형이 겹친다는 설명만 포함한다.

정확한 SVG 경계는 문제를 풀기 위한 시각 정보이므로 좌표 자체가 이중 겹침 넓이를 기하학적으로 표현하는 것은 허용한다. 답 선노출 금지는 숨겨진 중간값이나 최종 답을 숫자 문자열, `data-*`, title, description, 접근성 이름으로 직접 직렬화하는 것을 뜻한다. 정량 그림의 좌표에서 학습자가 관계를 추론할 수 없게 하라는 뜻이 아니다.

## 8. 데이터 흐름과 호환성

새 문제는 지금처럼 파생된 `ThreeShapeOverlapModel`을 저장할 수 있다. 저장된 모델에는 영역 넓이만 두고 SVG 좌표는 저장하지 않는다. 기하는 순수하고 결정적인 생성 함수로 매번 복원한다. 이 방식은 화면 크기에 독립적이며 저장 payload를 불필요하게 키우지 않는다.

지원하는 구형 payload는 `type='three_shape_overlap'`과 `props.shapeArea`, 길이 3의 `props.exclusiveAreas`, `props.tripleOverlap`, `props.unit`을 가지고 `semantics`와 `model`만 없을 수 있는 형태다. 이 경우 props를 현재 `buildThreeShapeOverlapModel`에 넣어 canonical model을 만든다. 새 payload에 `model`이 있더라도 props에서 다시 만든 canonical model과 일치하는지 확인하고, 불일치하면 손상된 payload로 처리한다. 필수 props 누락, 잘못된 튜플 길이, 단위 오류, 지원하지 않는 위상은 복구 가능한 구형 형식으로 추측하지 않는다.

골든 fixture는 최소한 다음 두 형태를 고정한다.

1. `semantics`와 `model`이 없는 기존 payload
2. `semantics='quantitative'`와 canonical `model`이 모두 있는 현재 payload

기존 세션 형식과 localStorage 키는 바꾸지 않는다.

## 9. 실패 처리

- 템플릿 검증과 문제 생성 단계에서 모델, 지원 위상, 적합성 부등식 또는 기하가 유효하지 않으면 해당 템플릿을 실패시킨다.
- 런타임에서 손상된 구형 세션을 만났을 때는 수치와 모순되는 근사 그림을 보여주지 않는다. 문제 본문은 유지하고 그림 영역에는 정량 그림을 생성할 수 없다는 비정량 오류 상태를 표시한다.
- 실패 시 숨겨진 영역값이나 정답을 오류 문자열에 포함하지 않는다.
- 유효한 현재 템플릿은 모든 허용 매개변수 표본에서 생성·검증을 통과해야 한다.

## 10. 테스트 전략

### 10.1 수학 모델 테스트

- 현재 표본의 일곱 영역과 각 도형 넓이 재구성을 유지한다.
- 음수, 비유한 값, 현재 셀 기반 계약에 맞지 않는 값을 계속 거부한다.

### 10.2 기하 생성기 테스트

- 테스트를 먼저 추가하고 기존 셀 렌더러에서 실패하는 것을 확인한다.
- `BC만=0`인 현재 위상과 도형 이름을 순환 배치한 다른 단일 0 쌍을 생성한다.
- `ABC=0`, 단독 영역 0, 이중 겹침이 둘 이상 0, 이중 겹침이 모두 양수인 미지원 위상을 명시적으로 거부한다.
- 같은 입력이 완전히 같은 좌표를 만드는지 확인한다.
- 완성된 A·B·C 다각형만 clipping한 결과에서 각 원자 영역과 도형의 측정 넓이가 기대값과 부동소수점 epsilon 안에서 같은지 확인한다.
- 0 영역이 기하 결과에 없는지 확인한다.
- 외곽선이 닫히고 자기 교차하지 않는지 확인한다.
- 각 라벨 기준점이 자신의 영역 안에 있는지 확인한다.

### 10.3 렌더러 테스트

- A·B·C 외곽선이 실제로 렌더되는지 확인한다.
- 단위 셀과 `한 칸 = 1` 설명이 제거됐는지 확인한다.
- 문제에 주어진 `A만`, `B만`, `C만`, `ABC` 값은 표시되는지 확인한다.
- `AB만`, `AC만`, `BC만`의 숫자 문자열과 `data-*` 값은 DOM과 접근성 이름에 없는지 확인한다.
- 0 영역의 SVG 요소와 라벨이 없는지 확인한다.
- 구형 `visual.model` 없는 payload도 같은 기하를 렌더하는지 확인한다.

### 10.4 콘텐츠·통합 검증

- `npm run validate:templates`
- `npm run audit:problems`
- 관련 Vitest 집중 테스트
- 전체 `npm test`
- `npm run lint`
- `npm run tdd:guard`
- `npm run build`
- 390×844와 1024×768에서 가로 넘침, 라벨 충돌, 콘솔 오류 확인
- 신규 payload와 모델 없는 구형 저장 세션의 E2E 확인

## 12. 이후 확장

이번 변경은 공통 기본형과 검증기를 세 도형 겹침에 필요한 만큼만 구현한다. 다음 정량 문제 유형은 각각 다음 순서로 추가한다.

1. 문제에서 선언하는 정량값과 도형 정의를 명시한다.
2. 기존 렌더 그림에서 해당 값을 독립적으로 측정하는 실패 테스트를 둔다.
3. 문제 유형별 어댑터를 추가한다.
4. 공통 검증기를 통과한 기하만 렌더한다.
5. 허용 매개변수 전체 또는 경계 표본을 콘텐츠 검증기에 포함한다.

범용 최적화 엔진은 여러 유형에서 같은 제약 조합이 반복되고, 결정적 폐형식 생성기로 감당할 수 없다는 근거가 생길 때만 별도 설계한다.

## 13. 승인 기준

다음 조건을 모두 만족하면 첫 적용을 완료한 것으로 본다.

1. 화면에 셀이 아니라 세 개의 실제 폐곡선 도형이 겹쳐 보인다.
2. 생성된 A·B·C 경계를 독립적으로 clipping해 다시 측정한 각 도형과 원자 영역 넓이가 문제 모델과 일치한다.
3. 숨겨진 이중 겹침값의 숫자 문자열과 `data-*` 값이 DOM에 없고, 0 영역을 암시하는 면이나 라벨이 없다.
4. 현재 템플릿의 모든 허용 표본과 구형 저장 세션이 결정적으로 렌더된다.
5. 집중 테스트, 전체 테스트, lint, TDD guard, 템플릿 검증, 문제 감사, build와 두 viewport 검증이 통과한다.
6. 이후 문제 유형이 React 컴포넌트에 수학 좌표 계산을 추가하지 않고 같은 어댑터·검증기 경계로 확장될 수 있다.
