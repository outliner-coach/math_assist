# 프로필 스코프 저장 어댑터와 키별 격리 마이그레이션

## 상황

같은 브라우저 프로필을 여러 어린이가 나눠 쓰면 학년별 고정 키 집합을
함께 보게 된다. 진도·세션·결과·영수증·마스코트 기록이 기기 전역 키에
섞여 있어 학습자별 분리, 전송, 삭제가 불가능했다. 동시에 기존 localStorage
형식을 바꿀 때 완료·복습·최근 활동을 잃지 않아야 하고, 한 키의 손상이
다른 학년 기록으로 번져서는 안 된다.

## 결정

기기 전역 registry `mathAssist_profiles_v1` 아래에 학습자 소유 스코프 키
`mathAssist_profile_v1:<profileId>:<legacyKey>`를 두는 어댑터를 둔다.
모든 학년 진도·세션·결과·영수증·마스코트·게스트홈·복구 증거 키가 이
형식으로 이전되며 위 표의 기존 키 이름은 `<legacyKey>` 자리에 그대로
유지된다.

- 마이그레이션은 키별로 격리한다. 유효한 값은 복사하고, 손상된 값은
  원본 바이트를 보존한 뒤 건너뛰고 `status='failed'`로 남긴다. 다른
  학년 기록은 축소되지 않으며 재시작은 멱등하다.
- 탭 임대는 holderId를 sessionStorage `mathAssist_tabHolderId_v1`에
  영속화해 전체 페이지 내비게이션 사이에 쓰기 권한을 유지한다. 임대를
  상실한 탭의 쓰기는 조용히 거부되고 홈에는 '다른 탭에서 프로필이
  바뀌었어요' 오버레이를 제공한다.
- 전송 파일 `PortableProfileExportV1`은 SHA-256 digest를 가지며
  완료·복습·세트 완료·영수증·최근 활동·마스코트만 담는다. 원답·세션
  스냅샷·풀이장 획은 제외한다. 적용은 미리보기 뒤 같은 ID 병합(합집합,
  최신 영수증 판정) 또는 새 프로필 생성 중 하나이며 적용 전에 롤백
  백업을 만든다.

## 선택하지 않은 안

- 마이그레이션을 하나의 원자 작업으로 묶고 손상 키에서 전체를 abort하는
  안은 스펙 §5의 키별 격리 요구 위반으로 기각했다. 한 키의 손상이 전체
  이전 중단과 다른 학년 기록 축소로 번진다.
- 기존 키를 새 형식으로 즉시 재작성하는 안은 손상 원문 보존 계약과
  충돌하므로 선택하지 않았다.

## 결과

학습자마다 자기 스코프 키만 읽고 쓰며 같은 브라우저 안에서 기록이
분리된다. 이후 제약으로 학습자 소유 신규 키는 `LEARNER_OWNED_STORAGE_KEYS`
등록이 필수다. registry와 스코프 키 계약은 현재 작업트리 상태이며
`main` 병합과 배포는 별도 승인 대상이다.
