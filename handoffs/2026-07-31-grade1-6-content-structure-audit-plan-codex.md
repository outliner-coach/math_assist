# 1~6학년 콘텐츠 구조·충분성 감사와 보강 계획

기준일: 2026-07-31

상태: 현재 `main` 전수 감사와 전체 회귀 검증 완료, 콘텐츠 보강 구현 전

## 결론

현재 공개 원본 1,540개는 수학·채점·답 선노출·렌더러·저장 회귀
게이트를 모두 통과한다. 그러나 이 숫자는 학습할 수 있는 원본 ID의
수이지, 서로 다른 수학 문제의 수나 성취기준별 충분성을 뜻하지 않는다.

가장 먼저 고칠 것은 다음 세 가지다.

1. 1~6학년 모두에 대해 단원 선언이 아니라 실제 문제 연결을 세는
   교육과정 게이트를 만든다.
2. 2학년의 접두 문구만 바꾼 72개 반복본과 3학년의 얇은 고정형
   문제 은행을 실제 기본·연습 콘텐츠로 교체·확장한다.
3. 학년별 원본 수, 수학적으로 다른 문제 수, 생성 변형 수, 한 번에
   푸는 문제 수를 분리해 보고한다.

모든 학년을 같은 문제 수로 맞추지는 않는다. 1~2학년 `play`,
3~4학년 `bridge`, 5~6학년 `study`의 발달 단계는 유지하고, 같은
학년군 안에서 문제 은행과 기본·연습 흐름을 일관되게 만든다.

## 확인한 이슈

### 1순위 — 교육과정 직접 연결과 검증 계약

- 1~2학년에는 3~6학년과 같은 공식 배정 원장이 없다. 현재 1학년
  직접 코드 10개와 2학년 단원 선언만으로는 학년군 전체의 누락을
  판정할 수 없다.
- 2학년 단원이 선언했지만 어느 문제에도 직접 연결되지 않은 코드는
  `[2수01-05]`, `[2수01-07]`, `[2수01-08]`, `[2수02-02]`,
  `[2수03-05]`, `[2수03-06]`, `[2수03-12]`이다.
- 3학년 배정 코드 `[4수03-16]`은 어느 미션에도 직접 연결되지 않는다.
- 현재 교육과정 검사는 소스에 코드 문자열이 있는지를 세므로 단원
  선언만 있고 실제 문제가 없어도 92/92로 통과할 수 있다.
- 2학년 validator도 `curriculumCode`가 비어 있지 않은지만 확인하고,
  단원의 선언 집합에 속하는지와 선언 코드를 모두 썼는지는 확인하지
  않는다.

### 2순위 — 2·3학년 콘텐츠 충분성

- 2학년 144개 중 절반인 72개는 기존 문제에 `한 번 더` 문구와 새
  ID만 붙인 반복본이다. 모든 템플릿의 수치 매개변수도 비어 있다.
  현재 장기 변형 테스트는 ID·접두 문구·선택지 순서 차이까지 서로
  다른 것으로 세므로 실제 수학 다양성을 과대계수한다.
- 3학년은 40개 모두 고정형이고 seed가 문제 수치나 구조를 바꾸지
  않는다. 25개 배정 기준 중 16개는 직접 문제가 한 개뿐이며
  `reason`, `explain`, `analyze_error` 행동이 없다.
- 3학년 화면은 모든 단원을 `3개 미션`이라고 안내하지만 들이와
  무게에는 7개가 있다. 구현 문서도 36개·단원별 3개 상태에 머물러
  있다.

### 3순위 — 1학년 재도전과 5학년 학습 형태

- 1학년 96개 중 36개는 기존 원본을 확장한 파생 템플릿이다. 그중
  고정형 파생본은 같은 수학 문제를 다시 보여 준다. 현재 문서의
  `96개 authored missions` 표현은 원작성 수와 공개 ID 수를 섞는다.
- 5학년 `areaunit-001`은 A/B/C에 걸쳐 완전히 같은 원문 payload
  두 묶음, 총 6개가 있다.
- 5학년은 개념당 30개 은행과 10문제 학습만 제공한다. 같은
  `study` 학년군인 6학년은 기본 5문제와 10문제를 모두 제공하므로
  기본·연습 형태가 일치하지 않는다.
- 5학년은 개념당 문제군 10개를 A/B/C가 공유하고, 6학년은 세트
  사이에 겹치지 않는 문제군 30개를 쓴다. 5학년도 30개를 강제할지,
  맥락·표현·추론 패턴 차이를 중복 허용 기준으로 삼을지는 콘텐츠
  계약으로 명시해야 한다.

### 문서·화면 상태 드리프트

  `docs/phases/README.md` 일부는 여전히 6학년 비와 비율만 공개된
  상태를 설명한다.
- 4학년 단원 선택 화면은 현재 배정 22개를 모두 직접 다루는데도
  나머지 성취기준을 열지 않았다는 이전 안내를 노출한다.
- 1·2학년의 `authored` 수와 3학년 36개 설명도 현재 재고 또는 실제
  원작성 수와 맞지 않는다.

## 실행 순서

### Wave 0 — 계수와 검증기부터 고정

1. 1~2학년 공식 배정 원장을 만들고 1~6학년 모두
   `배정 코드 → 실제 문제 ID` 역색인을 생성한다.
2. 단원 선언 코드가 실제 문제에 한 번 이상 직접 연결되지 않으면
   validator를 실패시킨다.
3. 콘텐츠 재고를 `공개 ID / 원작성 / 수학 서명 / 생성 변형 /
   세션 길이`로 분리해 출력한다.
4. 수학 서명에서는 ID, `도전 N`·`한 번 더` 접두 문구, 선택지 순서를
   제외한다. A/B/C 완전 동일 payload도 별도 오류로 막는다.

완료 기준: 1~6학년 직접 연결 분모가 존재하고, 누락 코드와 의미 없는
복제가 자동으로 재현된다.

### Wave 1 — 2학년과 3학년

1. 2학년 누락 7개 기준을 실제 기본·연습 문제에 연결한다.
2. 2학년 반복본 72개를 수치 매개변수, 표상, 문제군이 다른 연습
   문제로 교체한다. 기존 ID는 유지한다.
3. 3학년 `[4수03-16]` 문제를 먼저 추가한다.
4. 3학년을 단원별 10개 K/A/R 4/4/2 은행으로 확장한다. 한 번의
   활동은 K/A/R 3문제로 유지하고 `기본`과 `새 문제로 연습`을
   명시한다.
5. 세 단원씩 묶어 생성·문장·정답·시각·브라우저 검수를 끝낸 뒤
   다음 묶음으로 이동한다.

완료 기준: 2학년 12×12가 수학 서명 기준으로 유효하고, 3학년
12×10 및 직접 연결 25/25, K/A/R 48/48/24를 만족한다.

### Wave 2 — 1학년과 5학년

1. 1학년 두 섬에 문제를 하나씩 추가해 섬별 14개로 맞추고,
   고정형 파생 문제부터 실제 연습 문제로 교체한다.
2. 5학년 `areaunit-001`의 동일 A/B/C payload 두 묶음을 서로 다른
   문제군·표현으로 교체한다.
3. 5학년에 기존 10문제 경로를 보존한 5문제 기본 모드를 추가한다.
4. 5학년 A/B/C의 허용 중복 기준을 결정하고 자동 감사로 고정한다.

완료 기준: 1학년 섬별 14개와 실제 재도전 변형, 5학년 기본 5/연습
10 및 완전 동일 세트 중복 0을 만족한다.

### Wave 3 — 화면·문서와 전체 출시 게이트

1. 3학년 고정 `3개 미션`, 4학년 이전 범위 안내를 현재 구조에 맞춘다.
2. 아키텍처·비즈니스 규칙·단계 문서의 공개 범위와 재고 용어를
   갱신한다.
3. 최종 편집 원장을 콘텐츠 해시 변경분만 재검수하고 실제
   모바일·태블릿 renderer 증거를 갱신한다.
4. 전체 validator, audit, promptfoo, Vitest, lint, build, E2E를
   순차 실행한다.

## 변경 경계

이 문서는 감사와 실행 계획만 확정한다. 제품 콘텐츠, 경로, 세션,
저장 형식은 아직 바꾸지 않았다. 구현은 Wave별 독립 커밋으로 나누고
각 Wave가 그 학년의 집중 테스트와 전체 공용 계약을 함께 통과한 뒤
다음 Wave로 넘어간다.
